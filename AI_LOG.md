# AI_LOG

Для подготовки решения использован Codex (модель GPT-6) в этой сессии. Пользователь предоставил PDF с требованиями и запросил полную архитектуру и исходный код проекта.

Ключевые запросы к ассистенту:

1. «Извлеки требования тестового задания из PDF и составь полный проект платежного API на FastAPI и PostgreSQL».
2. «Реализуй точные денежные расчёты в копейках, KVITTO10, график рассрочки, идемпотентность и разрешённые переходы статусов».
3. «Добавь README, миграции, Docker Compose, проверку подписи вебхука и pytest-сценарии».

Решения сверялись с формулировками задания: значения цен переведены в копейки, остаток деления рассрочки направляется в первые платежи,
а повторный `Idempotency-Key` возвращает исходную запись. Потенциально слабое место: SQLAlchemy sync-сессия используется в одном `async` endpoint
вебхука ради чтения сырых байтов запроса для HMAC. Это приемлемо для небольшого учебного сервиса, но при высокой нагрузке следует сделать обработчик
полностью синхронным с отдельной зависимостью для проверки подписи либо перейти на Async SQLAlchemy.

Codex выполнил задачу на отлично, написал правильную архитектуру, учел все детали задания.
Мною был добавлен логгер, запуск с gunicorn, также был убрал проброс порта БД и смена обращения к базе через название сервиса в docker-compose.
Также, было поставлена строгая проверка секрета в вебхуке.
